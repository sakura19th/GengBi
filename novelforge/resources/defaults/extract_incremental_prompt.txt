# 增量更新要求
请对上述"已有上下文条目"逐条审视，并结合"新增章节内容"做如下操作：

## 1. 保留
- 未被新剧情改变、仍然成立的条目：原样保留（可微调措辞），**uid 保持不变**

## 2. 更新
- 已被新剧情改变的信息（人物状态/关系演变/地点变化/剧情进展/伏笔回收等）：在原有条目基础上**更新 content**，体现"变化与演变"，**uid 保持不变**
- 优先级：新章节揭示的现状优先于旧章节的过时描述

## 3. 新增
- 新章节中出现的新人物/新地点/新事件/新关系/新伏笔/新剧情状态：**新增条目**（新 uid，如 char_9、loc_3、evt_5 等，避免与已有 uid 冲突）
- 主角的既有行为如有新进展，补入 protagonist_behavior 维度条目

## 4. 删除
- 已被后续剧情明确推翻或已彻底无关的过时条目：可以删除（宁少勿滥，只删明确过时的）

# 输出格式
请输出更新后的**完整** JSON 数组（含保留的原有条目 + 更新的条目 + 新增的条目），每个元素为一个 ContextEntry 对象，包含以下字段：
- uid：字符串，唯一标识（原有条目保持原 uid）
- category：字符串，取值 characters/relationships/locations/events/atmosphere/style/foreshadowing/plot_state/protagonist_behavior
- key：字符串数组，关键词列表
- comment：字符串，简短说明
- content：字符串，详细内容（最长 500 字）
- order：整数，排序权重（默认 100，数字越小越优先）
- position：字符串，注入位置（before/after/at_depth）
- depth：整数，仅 at_depth 时有效（默认 4）
- role：字符串，消息角色（system/user/assistant，默认 system）

# 提取原则
- 信息密度优先：保留全部仍然有效的关键信息，新增章节的重要信息不得遗漏
- 创作导向：更新后的条目应直接服务于续写质量（人物一致性、情节连贯、风格统一）
- 具体而非抽象：content 中引用具体文本细节（对话片段、场景描写），避免空泛概括
- 动态追踪：重点捕捉"变化"——人物如何变化、关系如何演变、局势如何发展
- 忠于原文：不得编造新增章节中不存在的内容

注意：
- 只输出 JSON 数组，不要包含任何解释性文字
- 不要使用 markdown 代码块标记
- content 字段控制在 500 字以内
- 确保所有 uid 唯一，无重复
- 输出的是**完整更新后**的条目集，不是增量片段
